Twenty is the open source CRM I recommend most often to small teams, and the question I get back most is how to run it on a server without a lot of fuss. This guide walks through a single-server setup with Docker Compose, from a fresh Ubuntu machine to a working login page over HTTPS.

{{image: twenty-compose-setup | The Twenty login screen after the stack has started on a fresh server}}

What you need

  • A Linux server with at least 2 GB of RAM and 20 GB of disk (a small VPS is fine)
  • Docker and the Docker Compose plugin installed
  • A domain name pointing at the server, so you can get a TLS certificate
  • An SMTP account for invitation and password reset emails

Step 1: Get the code and the environment file

Clone the official repository and copy the example environment file. Keep the example file as a reference, and edit the copy.

git clone https://github.com/twentyhq/twenty.git
cd twenty/packages/twenty-docker
cp .env.example .env

Step 2: Set the values that matter

Open .env and set these before starting anything:

  • APP_SECRET: generate a long random value and never reuse it between environments
  • SERVER_URL: the public address, such as https://crm.example.com
  • POSTGRES_PASSWORD: change the default, and keep it out of version control
  • Email settings: the host, port, and credentials for your SMTP provider

Step 3: Start the stack

Bring the containers up in the background and check that they are healthy:

docker compose up -d
docker compose ps
docker compose logs -f server

The first start takes a few minutes while the database is prepared. Wait for the server logs to report that it is listening before you open the browser.

Step 4: Put HTTPS in front of it

Do not expose the app over plain HTTP. A reverse proxy such as Caddy or Nginx with an automatic certificate is the simplest option. Point it at the local port the server container listens on, and let it manage the certificate renewals.

  • Open ports 80 and 443 on the firewall, and close everything else except SSH
  • Confirm that SERVER_URL matches the address your proxy serves
  • Test the invitation email before you invite the team

Step 5: Create the workspace and back up

Sign up in the browser, create the first workspace, and invite a teammate to confirm email works. Then set up a nightly database dump and copy it somewhere off the server. A CRM without a backup is a single bad disk away from losing the whole sales history.

Common problems

  • Invitation emails never arrive: check the SMTP credentials and the sending domain's SPF and DKIM records
  • Blank page after login: SERVER_URL probably does not match the address in your browser
  • Containers keep restarting: the server usually has too little memory, so add swap or move to a larger plan

Keeping it updated

Read the release notes before every upgrade, since the project moves quickly. Take a database backup, pull the new version, and restart the stack during a quiet hour. Once you are comfortable with the routine, the upkeep is about ten minutes a month.
