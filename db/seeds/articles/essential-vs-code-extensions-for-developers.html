I have reinstalled VS Code on three laptops this year, and every time I end up with the same short list of extensions. Some are obvious, and a few I added only after I got tired of a repetitive task. Here is what stays on my machine and why.

{{image: vscode-extensions-panel | The extensions panel, filtered to the handful I keep enabled}}

Language and linting

  • ESLint: shows lint errors inline as you type, using the same config as the project's CI
  • Prettier: formats on save so pull requests stop containing formatting noise
  • Ruby LSP: completion, go-to-definition, and diagnostics for Ruby and Rails projects

Git and review

  • GitLens: inline blame and file history. It is most useful when you are picking up code you did not write
  • GitHub Pull Requests: review a PR, leave comments, and check out a branch without leaving the editor

Everyday productivity

  • Error Lens: puts the error message at the end of the line, so you do not have to hover to read it
  • Path Intellisense: completes file paths in imports and config files, which saves a surprising amount of typing
  • Todo Tree: finds TODO and FIXME comments across the project in one panel

Front end and styling

  • Tailwind CSS IntelliSense: autocomplete for class names and a hover preview of the generated CSS
  • Live Preview: a small server for quick HTML checks without leaving the editor

Docker and containers

  • Docker: manage images and containers from the sidebar, and open a shell in a running container
  • Dev Containers: open a project inside a container so the whole team uses the same tools

What I removed

I used to keep a theme extension, two snippet packs, and an icon set. None of them saved time, and each one slowed startup a little. Disabling them made the editor noticeably quicker to open on the older laptop.

A few settings I change first

  • Turn on format on save, and set the default formatter per language rather than globally
  • Hide the minimap if you work on a small screen
  • Turn off auto-update for extensions you depend on, and update them deliberately

Verdict

A small set of well-maintained extensions beats a long list. Start with a linter, a formatter, and a git tool, then add anything that removes a repeated step. Check the install count and last update date before you add something new, and remove what you stop using.
